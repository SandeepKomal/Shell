Running scripts

command not found

./deploy.sh: line 5: ehco: command not found

Symptom

A script or the terminal stops on a word it cannot run. The exit status is 127.

Why it happens

Bash looked for a function, a builtin and then a program with that name in every directory of $PATH, and found none.

  • A typo in the command name
  • The program is installed outside $PATH (for example /usr/local/bin under cron)
  • Spaces around = in an assignment: NAME = value runs a command called NAME
  • A script in the current directory run without ./
  • A function defined in your terminal, which child scripts never see
  • Run under sudo, which replaces your PATH with its secure_path (sudo: <name>: command not found)

Confirm

type -a <name>            # prints nothing: no function, builtin or program by that name in PATH
echo "$PATH"
sudo printenv PATH        # the PATH sudo really uses

Fix

Correct the name, install the program, call it by its full path, or set PATH at the top of the script. For assignments, remove the spaces: NAME=value. Under sudo, call the program by its full path rather than widening secure_path.

Prevent

Set PATH explicitly in scripts that run from cron or CI, and check required tools up front with command -v.

Permission denied

bash: ./report.sh: Permission denied

Symptom

Running a script by its path fails at once with exit status 126.

Why it happens

The file exists but is not executable for you, or a directory on its path cannot be entered.

  • The script has no execute bit (-rw-r--r--)
  • The file system is mounted noexec, as /tmp is on many hardened systems
  • A fixed file name in the shared /tmp that another user's job created first
  • Writing to a file the shell cannot open, such as sudo echo x > /etc/file (the redirection runs as you)

Confirm

ls -l <script>                          # no x in the mode: the execute bit
findmnt -no OPTIONS --target <script>   # noexec in the list: the mount
namei -l <script>                       # a directory without x for you: the path

Fix

chmod +x script.sh. For noexec mounts run bash script.sh or move the script. For root-owned files use echo x | sudo tee /etc/file.

Prevent

Commit scripts with the execute bit (git update-index --chmod=+x) and keep them out of /tmp.

No such file or directory

/opt/tools/report.sh: line 2: ./lib/common.sh: No such file or directory

Symptom

A script, source, cd or a redirection fails on a path that you can see exists.

Why it happens

The path is resolved from the current directory, which is not the one you expect, or the name has invisible characters or spaces.

  • A relative path, run from cron or another directory
  • An unquoted path with spaces split into several arguments
  • A carriage return at the end of the name from a Windows file
  • The parent directory of a redirection does not exist
  • A glob that matched nothing, passed on literally (*.log)

Confirm

pwd
ls -l -- "<path>"
printf '%q\n' "<path>"

Fix

Use absolute paths, or build them from the script's directory: $(dirname "${BASH_SOURCE[0]}"). Quote paths. Strip \r from data files.

Prevent

Start scripts with cd "$(dirname "${BASH_SOURCE[0]}")" || exit 1 when they rely on neighbouring files, and use shopt -s nullglob before looping over globs.

cannot execute: required file not found

bash: ./deploy.sh: cannot execute: required file not found

Symptom

A script that exists and is executable fails immediately with exit status 127. Older bash says /bin/bash^M: bad interpreter: No such file or directory; env says /usr/bin/env: 'bash\r': No such file or directory.

Why it happens

The interpreter named on the #! line does not exist. Almost always the line ends with a Windows carriage return, so the kernel looks for /bin/bash\r.

  • The file was saved with CRLF line endings
  • The #! line names an interpreter that is not installed, such as /bin/zsh
  • A typo in the #! path
  • A program (not a script) whose dynamic loader is missing, such as a glibc build on Alpine (musl)

Confirm

head -1 <script> | cat -A   # ^M$ at the end: CRLF
file <program>               # 'interpreter /lib64/ld-linux-x86-64.so.2': that loader must exist

Fix

Convert the line endings: sed -i 's/\r$//' script.sh or dos2unix script.sh. Install or point #! at the real interpreter. For a program, use the build for this system's C library (a musl or static build on Alpine).

Prevent

Add *.sh text eol=lf to .gitattributes and set your editor to LF for scripts.

[[: not found

/home/dev/report.sh: 3: [[: not found

Symptom

A bash script fails under cron, sh script.sh or a Docker CMD, with errors such as [[: not found, source: not found, [: x: unexpected operator or Bad substitution.

Why it happens

The script is running in sh (dash on Debian and Ubuntu, busybox ash on Alpine), which lacks bash features.

  • No #! line, so /bin/sh runs it
  • Running it as sh script.sh, which ignores the #! line
  • #!/bin/sh on a script that uses bash features

Confirm

head -1 <script>
ls -l /bin/sh

Fix

Start with #!/usr/bin/env bash and run the file directly (./script.sh), or write POSIX sh only.

Prevent

Always write a #! line; check sh scripts with checkbashisms or ShellCheck's --shell=sh.

Argument list too long

bash: /usr/bin/rm: Argument list too long

Symptom

rm *.log, cp * or grep x * fail in a directory with many files.

Why it happens

The glob expanded to more text than the kernel allows for one program's arguments.

  • Tens of thousands of matching files
  • A very large environment, which counts against the same limit
  • One argument longer than 128 KiB on Linux (MAX_ARG_STRLEN), such as a whole file passed with "$(cat file)"

Confirm

ls | wc -l
getconf ARG_MAX
env | wc -c   # size of the environment, without printing it

Fix

Let find do it: find . -name '*.log' -delete, or find . -name '*.log' -print0 | xargs -0 rm --.

Prevent

Use find for bulk operations on directories that grow.

cannot execute binary file: Exec format error

bash: ./node_exporter: cannot execute binary file: Exec format error

Symptom

A downloaded program fails at once with exit status 126, or a container stops at start with exec /usr/local/bin/entrypoint.sh: exec format error in its log.

Why it happens

The kernel could not run the file: it is a program built for another CPU architecture, not a program at all, or a script without a #! line started by something other than a shell.

  • An amd64 binary on an arm64 host, or the reverse, such as an image built on an Apple silicon Mac and run on an x86 server
  • The download saved an HTML error page or an archive instead of the program
  • A container entrypoint script with no #! line, or a blank line or byte-order mark before it

Confirm

file <program>
uname -m
head -c 64 <program> | od -c | head -3

Fix

Use the build for this machine's architecture (uname -m prints x86_64 or aarch64), or build images for the target with docker buildx build --platform linux/amd64. For scripts, make #!/usr/bin/env bash the very first line.

Prevent

Pick release files by uname -m in install scripts, check downloads against their published checksum, and build images for every platform you run.

declare: -A: invalid option (bash 3.2 on macOS)

./sync.sh: line 3: declare: -A: invalid option

Symptom

A script that works on Linux fails on a Mac: declare -A is an invalid option, mapfile is not found, and ${name,,} is a bad substitution.

Why it happens

macOS ships bash 3.2 as /bin/bash. Associative arrays, mapfile, case conversion and other features arrived in bash 4.

  • #!/bin/bash runs the system bash 3.2 even when a newer bash is installed
  • A newer bash from Homebrew is in $PATH, but the script is run as bash script.sh from a shell where it is not

Confirm

bash --version | head -1
head -1 <script>
type -a bash

Fix

Install a current bash (brew install bash) and start the script with #!/usr/bin/env bash, or keep to bash 3.2 features when it must run on a stock Mac.

Prevent

Scripts that need bash 4 can say so at the top: ((BASH_VERSINFO[0] >= 4)) || { echo 'needs bash 4 or newer' >&2; exit 1; }.

No space left on device

cp: error writing '/var/backups/db.sql': No space left on device

Symptom

Writes fail part way: a backup or log stops growing, cp or tar exits non-zero, and even small scripts fail with cannot create temp file for here-document.

Why it happens

The file system has no free blocks, or no free inodes, for the write. Bash writes here-documents to a temporary file, so they fail too.

  • Logs or old backups filled the disk
  • A deleted file is still open in a running process, so its space is not freed
  • Millions of small files used up the inodes while df -h still shows free space
  • A large write to a small /tmp
  • On ext4, the blocks reserved for root (5% by default): Avail is 0 for other users while Used is below Size

Confirm

df -h <path>   # Use% 100, or Avail 0 below Size: the reserved blocks
df -i <path>   # IUse% 100: inodes, not bytes
du -xh --max-depth=1 <path> | sort -h | tail   # where the space went
lsof +L1   # deleted files still open: df counts them, du does not

Fix

Free space where it is used: rotate or compress logs and remove old backups. Restart a process that holds a deleted file open (scripts/deleted_open_files.sh lists them). For inodes, find the directory with the many small files and clean it up.

Prevent

Alert on disk and inode use well before 100%, rotate logs, and keep a fixed number of backups (scripts/backup_rotate.sh -k).

Syntax

syntax error near unexpected token

deploy.sh: line 9: syntax error near unexpected token `fi'

Symptom

The script stops before running the command at that line, with exit status 2.

Why it happens

Bash read a word or operator where its grammar does not allow one. The real mistake is often a line or two earlier.

  • A missing then, do, ; or ;;
  • A missing space: if [$x = 1] or } without a ; before it
  • Windows line endings ($'do\r')
  • An unquoted ( or ) in an argument, such as echo (beta)

Confirm

bash -n <script>
cat -A <script> | sed -n '1,12p'

Fix

Look at the named line and the one before it; add the missing keyword, space or separator.

Prevent

Run bash -n and ShellCheck in CI on every script.

syntax error: unexpected end of file

deploy.sh: line 14: syntax error: unexpected end of file

Symptom

The error points at the last line of the script.

Why it happens

Something opened was never closed: if without fi, do without done, { without }, or a here-document without its end marker.

  • A missing fi, done, esac or }
  • A here-document whose end marker is indented or has trailing spaces
  • } on the same line as a command without ;

Confirm

bash -n <script>
grep -nE '^\s*(if|fi|for|while|do|done|case|esac)\b' <script>

Fix

Find the block that is not closed and close it. Put here-document end markers at the start of the line (or use <<- with tabs).

Prevent

Indent consistently so open blocks are visible, and run bash -n in CI.

unexpected EOF while looking for matching

deploy.sh: line 3: unexpected EOF while looking for matching `"'

Symptom

The script stops with exit status 2; lines after the quote never run.

Why it happens

A quote, $(, or backtick was opened and never closed before the end of the file.

  • An unbalanced " or '
  • An apostrophe inside single quotes: 'it's'
  • A $( without its )

Confirm

bash -n <script>
grep -n "'" <script>

Fix

Close the quote. For an apostrophe inside single quotes write 'it'\''s', or use double quotes.

Prevent

event not found

-bash: !word: event not found

Symptom

A command typed in the terminal with ! in it fails before it runs, such as echo "Pa55!word". The same line works in a script.

Why it happens

In an interactive shell ! starts history expansion, and bash found no earlier command starting with the text after it. Scripts run with history expansion off, so they never see this.

  • ! inside double quotes in a typed command
  • A password or message containing ! pasted into the terminal

Confirm

set -o | grep histexpand

Fix

Use single quotes ('Pa55!word'), escape the ! with a backslash, or turn history expansion off for the session with set +H.

Prevent

Single-quote literal strings, and keep passwords off the command line altogether.

Variables

unbound variable

./sync.sh: line 3: DEBUG: unbound variable

Symptom

With set -u the script exits with status 1 as soon as it reads a variable that was never set.

Why it happens

set -u (nounset) makes reading an unset variable an error, which ends a non-interactive shell.

  • An optional variable with no default
  • A missing argument: $1 when the script was run with none
  • A typo in a variable name
  • A variable set in your login shell but not under cron or CI
  • An empty array expanded as "${arr[@]}" in bash older than 4.4 (macOS's 3.2)

Confirm

[[ -v NAME ]] && echo set || echo unset
printenv NAME > /dev/null && echo exported || echo 'not in the environment'   # set in the shell but not exported: child scripts never see it
bash --version | head -1

Fix

Give optional variables a default with ${NAME:-default}, require others with ${NAME:?message}, and fix typos.

Prevent

Keep set -u: it finds typos. Document required variables at the top of the script.

parameter null or not set

./migrate.sh: line 2: DEPLOY_ENV: DEPLOY_ENV is not set

Symptom

The script stops with status 1 and prints a variable name followed by a message.

Why it happens

A ${NAME:?message} guard found the variable empty or unset. This is the guard working.

  • The variable was not passed in, or not exported by the parent script
  • A missing command-line argument (${1:?usage})
  • It is set but empty: ${NAME:?} rejects empty values too (${NAME?} only rejects unset)

Confirm

[[ -v NAME ]] && echo "set, ${#NAME} characters" || echo unset   # set, 0 characters: empty, not missing
printenv NAME > /dev/null && echo exported || echo 'not in the environment'

Fix

Pass the value: export NAME=value in the caller, or NAME=value ./script.sh.

Prevent

Keep the guard; add a usage message so the next person knows what to pass. If the message comes from a here-document, quote its delimiter (<<'EOF').

bad substitution

./report.sh: 4: Bad substitution

Symptom

A ${...} expansion fails. In dash the message is Bad substitution with a capital B.

Why it happens

The shell does not understand that form of ${...}: either it is a bash feature running in sh, or it is mistyped.

  • Bash-only forms like ${var//a/b} or ${var^^} run by sh (no #! line, or sh script.sh)
  • A typo such as ${x!} or a space inside the braces

Confirm

head -1 <script>
ls -l /bin/sh

Fix

Run the script with bash: #!/usr/bin/env bash and ./script.sh, not sh script.sh. Correct the expansion.

Prevent

Start every script with a #! line for the shell you write for.

bad array subscript

./build.sh: line 6: arr: bad array subscript

Symptom

Reading the last element of an array, or storing a value under a key, fails with this message.

Why it happens

The index does not point inside the array: a negative index reaches before the first element, or an associative array was given an empty key.

  • ${arr[-1]} on an empty array, or ${arr[-n]} with n larger than the array
  • map[$key]=value with key empty or unset
  • Bash older than 4.2 (macOS's 3.2), which rejects negative indexes; assigning to one, such as arr[-1]=x, needs 4.3

Confirm

declare -p arr
echo "${#arr[@]}"
bash --version | head -1

Fix

Check the length before indexing: (( ${#arr[@]} )) && last=${arr[-1]}, and check that a key is not empty before using it.

Prevent

Use set -u, and test lengths and keys where the data comes from outside the script.

unary operator expected

./health.sh: line 3: [: !=: unary operator expected

Symptom

An if [ ... ] prints this error and takes the else branch (status 2), so alerts and checks silently do nothing.

Why it happens

An unquoted variable was empty, so it vanished: [ $x != ok ] became [ != ok ].

  • An unquoted empty variable inside [ ]
  • A command substitution that printed nothing

Confirm

Fix

Quote the variable: [ "$x" != ok ], or use [[ $x != ok ]].

Prevent

Quote every expansion inside [ ], or prefer [[ ]] in bash scripts. The same mistake makes [ -n $var ] true when var is empty.

integer expression expected

./disk.sh: line 3: [: 100%: integer expression expected

Symptom

A numeric test errors and is treated as false; thresholds never trigger.

Why it happens

-gt, -lt, -eq and friends need plain integers. The value has a unit, a decimal point, spaces or a \r.

  • A percentage or unit from df, free -h or du -h
  • A decimal such as load average 1.52
  • An empty value
  • A carriage return from a Windows file

Confirm

printf '%q\n' "$value"

[: missing `]'

./check.sh: line 8: [: missing `]'

Symptom

A test fails with exit status 2, so the if takes its else branch every time.

Why it happens

[ is a command, and its last argument must be a separate ]. Bash reached the end of the command without finding one.

  • No space before the closing bracket: [ "$a" = "$b"]
  • && or || inside the brackets: [ -n "$a" && -n "$b" ] ends the [ command at &&
  • A ] written as ) or left out after a line break

Confirm

sed -n '8p' <script> | cat -A
shellcheck <script>

Fix

Put spaces around every argument of [, including before ]: [ "$a" = "$b" ]. Join tests outside the brackets, [ -n "$a" ] && [ -n "$b" ], or use [[ -n $a && -n $b ]] in bash.

Prevent

Run ShellCheck in CI: it reports the missing space as SC1020.

Temporary credentials (an assumed role, SSO or session token) have a lifetime. They were valid when the job started and expired before it finished.

  • Credentials copied into environment variables from an earlier aws sts assume-role or aws sso login
  • A job that runs longer than the role's maximum session duration
  • Old AWS_ACCESS_KEY_ID and AWS_SESSION_TOKEN still exported: they win over the profile, so the CLI never refreshes

fe_sendauth: no password supplied

pg_dump: error: connection to server at "db.internal" (10.0.2.15), port 5432 failed: fe_sendauth: no password supplied

Symptom

The backup works when you run it by hand and fails from cron, or it hangs waiting for a password prompt.

Why it happens

The server asked for a password and libpq had none: no ~/.pgpass entry it could use, and no PGPASSWORD.

  • ~/.pgpass belongs to another user, or cron runs as a different user or HOME
  • Its permissions are wider than 0600, so libpq ignores it (it prints a warning saying so)
  • The host, port, database or user in the file does not match the connection: the host is compared as text, so db.internal and its IP are different entries

Create ~/.pgpass for the user that runs the job with host:port:database:user:password, chmod 600 it, and pass --no-password (or -w) so a missing password fails at once instead of waiting.

Symptom

Why it happens

The Deployment did not make progress within progressDeadlineSeconds (600 by default). Kubernetes marks it failed but does not roll back on its own.

  • The new image crashes on start (CrashLoopBackOff) or fails its readiness probe
  • The image cannot be pulled (ImagePullBackOff): a wrong tag, or no pull secret for a private registry

  • A ResourceQuota or LimitRange rejects the new pods, so the ReplicaSet never creates them

kubectl get events -n <ns> --sort-by=.lastTimestamp | tail   # 'exceeded quota' or FailedCreate: no pods were made at all

Fix

Roll back with kubectl rollout undo deployment/<name> and confirm with rollout status. Then fix the image or the probe and release again.

Prevent

Make the deploy script undo automatically when rollout status --timeout fails, and fail the job (scripts/k8s_rollout.sh).

Cannot evict pod: it would violate the disruption budget

error when evicting pods/"api-7c9d8b6f5-x2lq4" -n "shop" (will retry after 5s): Cannot evict pod as it would violate the pod's disruption budget.

Symptom

kubectl drain retries the same pod forever, or until --timeout.

Why it happens

Eviction respects PodDisruptionBudgets. Removing this pod now would leave fewer healthy pods than the budget allows, so the API refuses.

  • A PDB with minAvailable equal to the replica count, or maxUnavailable: 0
  • Other replicas are not ready, so the budget is already used up
  • All replicas run on the node being drained

Confirm

kubectl get pods -n <ns> -l <selector> -o wide   # not-ready replicas, or all of them on this node

Wait for the other replicas to become ready, or scale the Deployment up first so the budget allows one eviction. Do not bypass it with --disable-eviction.

Prevent

Run at least two replicas spread across nodes, and set budgets that allow one disruption (maxUnavailable: 1).

Host key verification failed

Host key verification failed.

Symptom

A loop over hosts fails on new or rebuilt servers, or hangs on Are you sure you want to continue connecting (yes/no)? when run by hand.

Why it happens

ssh does not know the host's key (or the key changed), and in BatchMode it will not ask, so it refuses to connect.

  • A new host not yet in known_hosts
  • A rebuilt host with a new key
  • A different user (cron, CI) with its own empty known_hosts
  • An IP address or name now used by a different server (common with cloud IPs), or a real man-in-the-middle

Confirm

ssh-keygen -F <host>   # nothing: unknown host; a line: compare its key with the one below
ssh-keyscan <host> 2>/dev/null | ssh-keygen -lf -   # the fingerprint the host offers now; check it against the console or inventory

Fix

Check the key's fingerprint against the host (console, cloud API or your inventory), then add it: ssh-keyscan <host> >> ~/.ssh/known_hosts, or remove a stale one with ssh-keygen -R <host>.

Prevent

Distribute host keys from your inventory or use SSH certificates. Never set StrictHostKeyChecking=no to make a loop pass: that accepts any server, including an attacker's.

deploy@web-02: Permission denied (publickey).

Symptom

Symptom
